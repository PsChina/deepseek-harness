# Agent Note: 自动续行链的有界默认值

Status: implemented

[English](2026-09-25-bounded-default-turn-continuation-chain.md) | 中文

## 问题

当模型反复触及输出 token 上限时，turn-continuation 守卫会在每次截断后继续排入请求。无上限默认值会让无法在配置的输出上限内完成工作的模型持续消耗 token，且不需要新的人工决策。

## 决策

`@deepseek-ai/dsh-turn-continuation` 默认允许一条连续 max-tokens 结局链自动续行三次。链中的第四次截断会记录警告，且不再排入续行。任何其它轮次结局都会重置计数；之后的截断可以开始新链。部署可以配置更高的有限整数上限。

上限计算续行提示次数，而非截断事件数：前三次 max-tokens 结局各自获得一次续行，之后再次触顶才会停止。这项策略适用于所有使用该守卫的 agent，包括子 agent。[原 turn-continuation Agent Note](../feature/2026-08-28-turn-continuation-after-truncation.zh.md)保留自动恢复截断轮次的依据与独立的投递语义。

## 考虑过的替代方案

- **保留无上限默认值**——不采用，因为反复耗尽输出预算的模型会在没有用户输入时无限触发模型请求并产生 token 费用。
- **只允许自动续行一次**——不采用，因为一次续行可能仍在完成正常的长任务时触及输出上限；允许三次恢复，同时为卡住的链设置有限上限。
- **任何截断后都不自动续行**——不采用，因为单次输出上限截断仍应自动恢复，不要求人工发送"继续"。

## 后果

- 默认情况下，每条链最多收到三条自动续行提示；之后的截断保持为未完成轮次，并产生警告。
- 需要更长续行链的部署可以提高 `maxConsecutive`；所有接受的值仍为有限整数且 >= 1。
- 计数仍按 agent 存在内存中，并在任何非 max-tokens 结局后重置，因此现有链生命周期保持不变。
- 单元回归测试与 keyless SDK 快照固定默认次数和停止时的会话记录。
